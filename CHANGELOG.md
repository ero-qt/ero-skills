### Added

- `repo-writing` skill, which writes commits, PRs, issues, review replies and docs the way a person on GitHub would, after it reads the repo's own style. It starts from how natural text reads, with 3 tests to run on every draft. Its list of AI tells goes from single words up to the stance of a whole text. The prose check flags most of them, reads whole paragraphs for rhythm and prints how many tells it found per 100 words. `--explain` prints why a rule flags a sentence and how to fix it.
- `code-comments` skill, which makes code explain itself and keeps comments to the facts that the code can't show. It names parameters after their role, groups them by concept and keeps error messages and log lines short.
- `terse-replies` skill, which keeps chat replies caveman-short at 3 levels, with the answer first, exact steps and the state and next step at the end. Its plugin also sets a Terse output style. The work-ethic plugin shows the level in 1 line at every prompt, so the style stays on for the whole session. The full rules come back after a compaction and at the prompt after a reply that broke one of them. The level is kept between sessions. At the end of each turn a check reads the reply and writes every broken rule to `slips.jsonl` in the data folder of work-ethic, like a commit gate longer than 12 lines, a dash or a closing offer. It never stops the turn.
- `work-loop` skill, which runs repo tasks in one fixed order, from checking open PRs and issues to the review and the PR. Each commit gets a size from trivial to large and a loop level of `light`, `standard` or `strict`. The 2 together pick the steps it runs. A rename skips the review. A new public type gets a plan of several commits first. Each step that an agent runs has its brief in `stage-briefs.md`, and `stages.md` gives the ledger record of every step. The rules of a repo go in a house brief at `.git/work-loop/house.md` that every agent reads. After a crash or a compaction, a commit goes on at the first step without a record. Its `commit-cycle` workflow runs the agent steps of 1 commit in order, with the review agents at the same time, and returns the ledger records. It stops at the first step without a proof, like a red test that passes, and a stopped run goes on from the step it stopped at. Each step runs as its own `work-loop:stage-<step>` agent with repo-writing and code-comments loaded. The review agent doesn't get the edit tools. Its checklist covers design and reuse too, like a helper with 1 caller, a parameter named after the wrong role or a parser written by hand for a format the standard library reads. When a smaller way exists, the review gives the size in lines of both ways. The commit gate fits in 12 lines, with all checks on 1 line and the subject right above `Approve?`. Choices that differ from person to person, like the loop level, the issue step, the review model or deleting merged branches, are knobs in `.git/work-loop/knobs.json`. Each knob has a default, so you don't have to set any. Its `ledger.js` script writes the proof of each step of a commit to `.git/work-loop/ledger.jsonl`, where it can't be staged by mistake. A hook of the work-ethic plugin checks every `git commit` before it runs. It stops a commit with a trailer in the message, a hard finding of the prose check or a staged path from the never-stage list (`.env`, `.claude/settings.local.json` and the lines of `.git/work-loop/never-stage`). It also stops a command that stages files and commits in one go, like `git add -A && git commit` or `git commit -a`, because the checks read the staged files before the command runs. Staged text that belongs to someone else, like a license, can keep what the prose check flags when the ledger gives a reason. When source changes without a doc change and the ledger doesn't say why, it warns Claude. It stops the commit instead when `.git/work-loop/knobs.json` sets `"loop": "strict"`. Each finding goes to `slips.jsonl` in the data folder of work-ethic.
- `work-ethic` skill, which ties the other 4 skills together. It lists which skill covers what, what to load again after a compaction and what a subagent needs in its prompt. It keeps the knobs of the skills. You change one by saying its phrase on a line of its own, like `loop strict` or `auto on`. A hook shows all knobs in 1 line at every prompt. The terse level is kept for every repo, auto mode only for the session and the rest for the repo, where they win over your defaults. Its plugin runs the hooks of terse-replies and work-loop, so they have 1 home and 1 slip log. After a compaction a hook lists the skills to load again, the house brief and the newest ledger record. `status.js` counts the slips of each rule over the last 7 days. The plugin installs the other 4 with it.
